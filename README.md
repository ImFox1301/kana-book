# Кана-тетрадь

Тренажёр хираганы, катаканы и слов: рисуете знак пальцем, сайт распознаёт его без ИИ (сравнение облаков точек + карты направлений штрихов, эталоны из KanjiVG).

## Навигация и уроки

Нижняя панель (на широком экране — слева): **Сегодня · Уроки · Практика · Словарь · Я**.

- **Сегодня** — повторение (см. ниже), цель дня (минуты занятий и число карточек/прописей, задаётся при первом запуске и в разделе «Я», хранится в аккаунте), рекомендуемый урок, слабые знаки, неделя и серия дней подряд.
- **Уроки** — 18 уроков хираганы и 18 уроков катаканы (`src/lessons.js`): основные ряды и ряды с дакутэном по 5 знаков, сочетания ёон, маленькая っ/ッ, долгие гласные, частицы, у катаканы — черта ー и звуки заимствований (ティ, ファ, ヴ…). Урок: знакомство (озвучка, порядок штрихов, мнемоника, произношение) → прописи (5 раз: 3 по подложке, 2 по памяти) → проверка (квиз на чтение с повторением прошлых уроков, нужно 80%). Слова урока составлены только из пройденных знаков (проверяет `tools/check_lessons.js`, в том числе в CI). Все уроки открыты, пройденные отмечены, следующий рекомендуется.
- **PDF** конспекта и прописей генерируется в браузере (`src/pdf.js`, [pdf-lib](https://github.com/Hopding/pdf-lib), MIT) и работает без сети: знаки рисуются векторно по штрихам KanjiVG, прописи — на сетке с образцом и бледными копиями для обводки.
- **Практика** — повторение, квиз, азбука и прописи, квиз на слух, похожие знаки, конструктор предложений, чтение в поездке, слабые знаки.
- **Конструктор предложений** (`src/sentences.js`) — 6 уровней по одной конструкции (X は Y です, вопросы с か, просьбы с を ください, ありますか, направление へ/に, место действия で), по 8 фраз для поездки. Русская фраза — собрать японскую из блоков, среди них есть лишние частицы; где порядок свободный, засчитываются оба варианта. После ответа — чтение (частицы は, へ, を — «ва», «э», «о»), озвучка и пояснение. Ошибки попадают в повторение.
- **Чтение в поездке** (`src/reading.js`) — около 80 настоящих надписей по темам: еда и меню, транспорт, магазины, отель, улица. Надписи показаны печатным шрифтом, как на табличках. Квиз «Что означает?» — выбрать значение из 4; «Прочитать» — для надписей каной. Надписи иероглифами учатся узнавать в лицо, чтение показывается после ответа. Ошибки попадают в повторение.
- **Интервальное повторение** считается из истории ответов (она синхронизируется с аккаунтом, отдельного хранилища нет). Верный ответ в день повторения переводит знак или слово на следующий интервал: 1, 2, 4, 7, 14, 30, 60, 120 дней; ошибка возвращает его в повторение сегодня, а выученный (от 7 дней) откатывает на 1 день. Знаки начатых уроков и слова пройденных попадают в повторение автоматически. Чем лучше знак выучен, тем сложнее задание: прочитать → узнать на слух → написать по памяти. За подход — до 20 карточек.
- **Квиз на слух** — звучит знак или слово, нужно выбрать из 4 вариантов (похожие по виду и звучанию, без совпадающих по звуку, как じ/ぢ). Режим «На слух» есть и в обычном квизе; на компьютере варианты выбираются цифрами 1–4.
- **Похожие знаки** — группы вроде シ・ツ・ソ・ン, ぬ・め, ね・れ・わ (`SIMILAR` в `src/kana.js`): по знаку выбрать чтение или по чтению — знак, после ответа — подсказка, как различать. Ошибки в квизах запоминаются (с каким знаком перепутано, в том числе по распознаванию рисунка), и самые частые пары показываются в «Чаще всего путаете».
- **Я** — аккаунт, цель дня и настройки (транскрипция, голос, строгость проверки, напоминания, вибрация: верно — один импульс, ошибка — два; на iPhone — системный тактильный щелчок через `<input switch>`, iOS 18+), прогресс по знакам.

## Азбука

Таблицы хираганы и катаканы в порядке годзюон. Нажатие на знак проигрывает его произношение, подпись ряда — весь ряд. В режиме «Выбрать для прописей» отмечаются знаки или ряды целиком, задаётся число повторений (от 5) и подложка — полупрозрачный образец знака для обводки. Каждая попытка проверяется тем же распознавателем, что и в квизе; знак считается отработанным после нужного числа верных попыток. В историю ответов попадают только попытки без подложки.

Озвучка: `assets/audio/{m,f}/*.mp3` — VOICEVOX:青山龍星 (мужской) и VOICEVOX:波音リツ (женский), синтезированы офлайн через VOICEVOX CORE (`tools/make_audio.py`). Голоса выбраны по разборчивости: каждый отдельный слог прогонялся через распознавание японской речи (ReazonSpeech), из 12 вариантов эти два узнавались лучше всего.

### Озвучка слов

Слова стартового словаря озвучены теми же голосами (`assets/audio/words/`). У мужского голоса подряд идущие гласные (いいえ) ограничены по длительности — иначе они растягивались и звучали по отдельности. Синтез идёт по записи с иероглифами, чтобы ударение было японским (箸 «палочки», а не 橋 «мост»); если чтение иероглифов расходится с записью каной (日本 → にっぽん, 辛い → つらい), берётся запись каной. Свои слова, добавленные в словарь, озвучивает сервис `tts/` (VOICEVOX CORE, те же голоса) по запросу `GET /api/tts?v=m|f&t=<кана>[&k=<иероглифы>]`: при добавлении слово сразу озвучивается, файл кэшируется на сервере и в приложении (дальше работает без сети). Иероглифы необязательны и нужны только для верного ударения; если их чтение не совпадает с каной, синтез идёт по кане. Без сети и до первой загрузки — японский голос устройства, если он есть. Сервис занимает около 450–500 МБ памяти и ограничивает число новых синтезов с одного адреса.

## Приложение (PWA)

Сайт устанавливается на телефон как приложение и работает без интернета: страница, шрифты и иконки лежат в кэше service worker'а, распознавание идёт на устройстве.

- Android / Chrome / Edge: кнопка «Установить» в шапке или меню браузера → «Установить приложение».
- iPhone / iPad: Safari → «Поделиться» → «На экран Домой».
- Обновления: после деплоя приложение показывает «Доступна новая версия» — кнопка «Обновить» перезагружает его на новую сборку.
- На iOS у установленного приложения своё хранилище, отдельное от Safari: слова и образцы почерка переносятся через «Резервная копия» в словаре.

## Как устроен деплой

```
git push → GitHub Actions (тест распознавателя + сборка образа) → ghcr.io → Watchtower на сервере сам подтягивает новый образ
```

Серверу не нужен входящий доступ для деплоя, а репозиторию — пароль от сервера.

## Аккаунты

Без аккаунта доступны квизы, азбука с озвучкой, прописи, словарь и тренировки, но прогресс не копится и не хранится в браузере. С аккаунтом — уроки, цель дня, интервальное повторение, история, серия дней, напоминания и друзья, на всех устройствах. Вход и регистрация — отдельные экраны; при регистрации указывается, как к вам обращаться (это имя видят друзья, его можно сменить).

### Вход через Telegram

Бот работает через long polling — серверу не нужен входящий доступ. Приложение создаёт попытку входа и открывает бота по ссылке `t.me/<бот>?start=<код>`; бот просит нажать «Поделиться номером» (Telegram подтверждает, что номер принадлежит этому пользователю; набранный вручную номер не принимается). Новый пользователь получает аккаунт с именем из Telegram, уже существующий подтверждает вход кнопкой «Войти» (на случай, если ссылку прислал кто-то другой, есть «Это не я»). К аккаунту с паролем телефон привязывается из раздела «Я». Приложение узнаёт результат по коду и секрету, который есть только у начавшего вход браузера. Номер телефона другим пользователям не показывается и для поиска не используется.

Включение: токен бота от @BotFather — в `.env` на сервере как `TELEGRAM_BOT_TOKEN`; без него кнопки Telegram не показываются.

### Друзья

Вкладка «Друзья» появляется после привязки телефона. Добавить друга: одноразовая ссылка-приглашение на 7 дней или поиск по точному логину (находятся только пользователи с привязанным телефоном), заявку нужно принять. О заявках приходит push-уведомление и отметка на вкладке. Друзья видят только сводку: серию дней, сегодняшние минуты и карточки против цели, число пройденных уроков, ответы и точность за неделю.

- API: `server/` — Kotlin, Spring Boot, PostgreSQL. Пароли — BCrypt, сессия — случайный токен в httpOnly-cookie (`SameSite=Strict`), в базе только его SHA-256.
- Синхронизация: `POST /api/sync` — клиент отправляет изменённые элементы и получает всё новое после своего курсора. Конфликт решается по времени изменения: побеждает более позднее.
- Защита открытой регистрации: ограничение частоты регистраций и попыток входа по IP и по логину.

## Напоминания

Web Push: в разделе «Я» включаются на устройстве (нужен вход в аккаунт; на iPhone — в установленном приложении, iOS 16.4+). Сервер раз в 5 минут проверяет, у кого наступило выбранное время, и присылает одно напоминание в день — только если цель дня ещё не выполнена (по синхронизированной активности со всех устройств). Шифрование содержимого (RFC 8291) и подпись VAPID (RFC 8292) сделаны на стандартной криптографии JDK (`server/.../push/WebPush.kt`); ключи VAPID создаются при первом запуске и хранятся в базе. Сервер отправляет только на адреса настоящих push-сервисов браузеров (Google, Mozilla, Apple, Microsoft).

## Сервер

Caddy занимает порты 80 и 443 и сам выпускает сертификат Let's Encrypt для домена сайта; `/api/*` уходит в kana-api, остальное — в статику. Другие сервисы на сервере не затрагиваются, если они не слушают 80 и 443.

Первый запуск (один раз):

```bash
mkdir -p ~/kana-tetrad && cd ~/kana-tetrad
# положить сюда docker-compose.yml и Caddyfile из репозитория
cat > .env <<EOF
SITE_DOMAIN=kana.example.com
DB_PASSWORD=$(openssl rand -hex 24)
EOF
docker compose up -d
docker compose logs -f caddy      # ждать строку "certificate obtained successfully"
```

DNS: A-запись домена сайта → IP сервера.

Резервная копия базы:

```bash
docker exec kana-db pg_dump -U kana kana | gzip > kana-$(date +%F).sql.gz
```

Если на сервере есть другой сервис, который продлевает свой сертификат через acme.sh в режиме standalone (ему нужен порт 80), пропишите ему хуки, чтобы на время продления Caddy останавливался:

```bash
sudo ~/.acme.sh/acme.sh --renew -d <его домен> --force \
  --pre-hook "docker stop kana-caddy" --post-hook "docker start kana-caddy"
```

## Локальная разработка

```bash
python3 build.py              # → dist/
node tools/e2e/serve.js       # dist/ + заглушка API на http://localhost:8790
node tools/e2e/lessons-e2e.js # первый запуск, урок целиком, PDF (нужен playwright)
node tools/e2e/srs-e2e.js     # повторение, квиз на слух, похожие знаки
node tools/test.js            # синтетический тест точности распознавания
cd server && gradle test      # тесты API (нужен PostgreSQL, см. DB_URL в application.yml)
docker build -t kana-tetrad . && docker run --rm -p 8080:80 kana-tetrad
```

## Структура

- `src/app.html`, `src/app.js` — интерфейс квиза и словаря
- `src/pwa.js`, `src/sw.js` — установка, офлайн-кэш и обновления
- `src/sync.js` — аккаунт и синхронизация
- `server/` — API аккаунтов и синхронизации
- `tts/` — сервис озвучки своих слов (VOICEVOX CORE, только linux/amd64)
- `tools/e2e/` — стенд и сквозная проверка синхронизации двух устройств
- `assets/fonts` — Klee One и Onest (OFL), урезанные до каны, латиницы и кириллицы
- `assets/icons`, `tools/make_icons.py` — иконки приложения
- `src/recognizer.js` — распознаватель рукописной каны
- `assets/audio`, `tools/make_audio.py` — произношение каны: [VOICEVOX](https://voicevox.hiroshiba.jp/), голоса VOICEVOX:青山龍星 и VOICEVOX:波音リツ ([условия использования](https://github.com/VOICEVOX/voicevox_vvm#readme): бесплатно с указанием «VOICEVOX:имя»)
- `src/lessons.js` — уроки: тексты, мнемоники, произношение, слова
- `src/pdf.js`, `assets/pdf`, `assets/vendor` — PDF урока: шрифты для PDF и pdf-lib/fontkit (MIT)
- `src/kvg.json` — штрихи каны из [KanjiVG](https://kanjivg.tagaini.net) (CC BY-SA 3.0, © Ulrich Apel)
- `src/kana.js` — таблицы каны, транскрипции Хэпбёрна и Поливанова, проверка ответов
- `src/words.js` — стартовый словарь
- `tools/kvg_parse.py` — пересборка `kvg.json` из SVG-файлов KanjiVG
